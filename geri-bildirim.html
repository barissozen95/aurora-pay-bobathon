Deneme oturumu geri bildirimi

13 Kasım 2026 tarihli deneme oturumunda (dry-run) dokuz görev, katılımcı gözüyle ve yeni kurulmuş bir Bob üzerinde uçtan uca çalıştırıldı. Bu sayfa o oturumdaki gözlemleri, her gözlem için yapılan değişikliği ve hâlâ açık olan konuları toplar.

Özet

  • İçerik çalışıyor. Dokuz görevin tamamı bitirildi ve 117 otomatik kontrolün hepsi geçti.
  • Zaman kaybı içerikten değil ortamdan geliyor. GitHub oturumu, Python sürümü, Bob Shell kurulumu ve API anahtarı görevlerin kendisinden daha çok vakit aldı. Bunların hepsi ön hazırlık listesine taşındı.
  • Kılavuzun dili sadeleştirildi. Oyun terimleri katılımcı kitlesine uymuyordu.
  • Üç adım belirsizdi. M0'daki "sayarak doğrula", M2'deki birleşik kod bloğu ve M5'teki "işlev bozulmadı" maddesi yeniden yazıldı.
  • İki görevde sorun çıkmadı. M4 ve M6 olduğu gibi bırakıldı.

Görev görev geri bildirim

M0 · İlk gün

Repoyu klonlama

Ne yapıldı
Bob IDE açıldı ve açılış ekranındaki "Clone Git Repository..." seçeneği kullanıldı.
Gözlem
Yeni kurulmuş bir Bob'da GitHub hesabı bağlı değildir; hesap bağlanmadan özel repo çekilemez. İlk denemede önce boş bir klasör açıldı: Bob klasörü "Restricted Mode"da açtı ve Source Control paneli klasörün git deposu olmadığını söyleyip "Initialize Repository" önerdi.
Öneri
Kılavuz katılımcıyı doğrudan klonlamaya yönlendirmeli ve klasöre güvenme (Trust) adımını göstermeli. GitHub oturumu atölyeden önce açılmalı.

Kurulum

Ne yapıldı
./setup.sh --scanners çalıştırıldı.
Gözlem
Betik "Python 3.10+ gerekli." diyerek durdu, çünkü python3 eski bir sürümü gösteriyordu. Bob'dan Python 3.10 kurması istendiğinde, sürümün desteği bittiği için reddetti ve güncel sürümü kurdu. Ardından bob komutunun olmadığı (Bob Shell ayrı bir paket) ve Semgrep'in PATH'te bulunmadığı görüldü.
Öneri
Ön hazırlıkta Python 3.11 veya üzeri, Bob Shell ve bob --version kontrolü yer almalı. Katılımcılar ./verify/run.sh m0 çıktısını atölyeden önce göndermeli.
PYTHON=/opt/homebrew/bin/python3.14 ./setup.sh --scanners

Repoyu tanıma

Ne yapıldı
Aynı soru iki modda soruldu: Agent modunda ve Ask modunda "bu repo hakkında bilgi ver". Ayrıca /init komutu denendi.
Gözlem
İpucundaki "kodda sayarak doğrula" ifadesi zahmetli. Bob'un verdiği sayıyı elle saymak yerine tek bir komut yetti. /init repoyu tarayıp bir AGENTS.md üretti; repoyu tanımak için iyi bir adım.
Öneri
İfade "Bob'un verdiği sayıyı komutla doğrula" olarak değiştirilmeli; /init bonus soru olmalı.
grep -c '^@app\.' services/core/main.py
wc -l services/core/*.py

M1 · Boş sayfadan servis

Ne yapıldı
PRD ve API sözleşmesi @ ile bağlam olarak verildi; Bob'dan önce plan, onaydan sonra kod istendi.
Gözlem
Yaklaşım ilk denemede çalıştı. İş bir dala commit'lendi, ancak dal adı M8 doğrulayıcısının beklediği feature/… veya fix/… kalıbına uymuyordu.
Öneri
Katılımcılar M0 sonunda feature/<kısa-ad> dalını açmalı ve her görevden sonra commit'lemeli. Böylece M8 kısalır.

M2 · SEV-2 alarmı

Ne yapıldı
Bob Shell başlatıldı; olay kaydı verilip kök nedenler istendi, düzeltme yasaklandı. Sonra bob run ile düzeltme denendi.
Gözlem
Kılavuzda bob chat ile python fixtures/incident/repro.py aynı kod bloğunda alt alta durduğu için kabuk komutu Bob istemine yapıştırıldı. İstem bir sohbet kutusudur, kabuk değildir. bob run ise "Bob API key is required. Set BOB_API_KEY environment variable." hatasıyla durdu. Sanal ortam etkin değilken python komutu da bulunamadı.
Öneri
Bob Shell ve terminal komutları ayrı bloklara ve ayrı sekmelere alınmalı. API anahtarı ön hazırlığa eklenmeli. Komutlar .venv/bin/python ile yazılmalı.

M3 · Kendi QA'ni kur

Ne yapıldı
/create-mode komutuyla yalnızca tests/ altını düzenleyebilen bir QA modu oluşturuldu; el kitabı referans verildi.
Gözlem
Komut iskeleti hızlı üretti ve mod üretim koduna dokunmayı reddetti. Kural ve skill dosyaları da doğrulamadan geçti.
Öneri
/create-mode Hamle 1'de ipucu olarak anılmalı; katılımcı yine de fileRegex satırını kendisi kontrol etmeli.

M4 · Test kalesi

Ne yapıldı
QA moduyla testler yazdırıldı; bulunan dört gizli hata Agent modunda düzeltildi.
Gözlem
Sorun çıkmadı.
Öneri
Kılavuzda değişiklik gerekmiyor.

M5 · Güvenlik avı

Ne yapıldı
Bulgular listelendi ve düzeltildi; tarama 0 bulgu verdi.
Gözlem
Teslim listesindeki "İşlev bozulmadı: geçerli sorgu ve geçerli arşiv adı hâlâ çalışıyor" maddesi açık değil. Katılımcı bunu nasıl kontrol edeceğini bilemiyor.
Öneri
Beklenen çıktılarıyla çalıştırılabilir bir kontrol eklendi: geçerli arşiv adı {'exit_code': 0}, geçersiz ad 422, enjeksiyon denemesi boş liste döndürmeli.

Gözlem
Sorun çıkmadı.
Öneri
Kılavuzda değişiklik gerekmiyor.

M7 · CFO'nun sorusu

Ne yapıldı
bob run --format json ile iki sınırlı iş çalıştırıldı; Bobalytics'ten harcama okundu ve bütçe notu yazıldı.
Gözlem
Bobalytics sayfasında verinin 60 dakikada bir yenilendiği ve saatlerin UTC olduğu yazıyor. Katılımcı az önce çalıştırdığı işi orada göremez. bob run için gereken API anahtarı da aynı portaldan alınıyor.
Öneri
Kılavuza gecikme uyarısı eklendi. Anlık rakam için reports/bob-run.json içindeki stats bölümü kullanılmalı.

M8 · Teslimat

Ne yapıldı
İş anlamlı commit'lere bölündü, dal push edildi, Pull Request açıldı ve CI yeşil sonuç verdi.
Gözlem
Commit'lerin çoğu en sonda, bir dakika içinde atıldı. İşi sonradan anlamlı parçalara bölmek, görev sırasında commit'lemekten daha zahmetli.
Öneri
Her görevden sonra commit önerisi kılavuzun "Nasıl çalışır?" bölümüne eklendi.
